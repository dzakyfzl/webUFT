# Implementasi seluruh P1

Cakupan permintaan pengguna: F11–F18 / FR-023–FR-040 pada PRD v1.6. P0 dipertahankan, P2 tetap backlog. Keputusan P1 dan izin migrasi tercatat di `.agent/DECISIONS.md`.

## Alur yang tersedia

| Area | Halaman | Perilaku |
|---|---|---|
| Dokumen | Proker → Dokumen | Unggah private maksimal 20 MiB, tautan eksternal, unduh terotorisasi, arsip metadata |
| Keuangan | Proker → Realisasi | Pengeluaran aktual, tanggal, kategori, bukti dari Proker yang sama, total dan selisih RAB backend |
| Laporan | Proker → LPJ | Narasi, capaian, hambatan, tautan dokumentasi; tidak menjadi syarat close |
| Inventaris | `/admin/inventory` | Aset/buku per kode unik, kondisi dan status terpisah; metadata digital dan rujukan password manager |
| Pinjam/sewa | Inventaris → Pinjam / riwayat | Nama peminjam manual, tanggal, biaya sewa, overdue, kembali rusak ke PERBAIKAN; histori/petugas tetap tersimpan |
| Acara | `/admin/events` | Pengurus aktif membuat; owner/Inti/pengelola terkait mengedit; draft/publish/unpublish dan soft-delete |
| Form | Acara → Form Builder | Template bebas dihapus seluruhnya, 8 tipe jawaban, bagian/opsi/required/placeholder/hint/urutan, preview peserta |
| Respons | Acara → Respons & ekspor | Pagination/filter, CSV/Excel per versi, penunjukan petugas, audit ekspor/penghapusan |
| Publik | `/events` dan `/events/{id}` | Hanya acara terbit, form anonim, konfirmasi tanpa PII peserta lain; kartu acara landing page existing memakai API P1 |
| Short link | `/admin/links`, `/shortlink` dan `/link/{slug}` | Slug unik, owner/Inti, edit/nonaktif/soft-delete, tujuan HTTP/HTTPS publik yang diperiksa ulang |

Tidak ada approval RAB, realisasi, pinjaman, atau publish acara. Pengelolaan inventaris hanya untuk anggota aktif Asset dan Property; jabatan Inti sendiri tidak memberikan hak inventaris. Metadata umum bisa dibaca pengurus lain, sedangkan peminjam/kontak dan rujukan vault dibatasi pengelola.

Inti boleh mengelola konten acara tetapi tidak otomatis membaca PII respons. Respons hanya dibaca pembuat acara dan petugas yang ditunjuk pembuat. Penunjukan sebagai petugas respons tidak memberi akses edit konten acara. Tidak ada penghapusan PII otomatis; penetapan jadwal retensi masih pekerjaan operasional.

## Versi dan arsip

Draft form tersimpan terpisah dari versi yang diterbitkan. Publish menambah versi immutable, dilindungi trigger PostgreSQL. Jawaban mengacu ke versi saat dikirim; CSV/XLSX selalu dipilih per versi. Submit versi lama mengembalikan 409 dan UI mempertahankan isian untuk dimuat ulang pada pertanyaan dengan ID yang sama. Retry request ID yang sama tidak menambah respons kedua.

Proker CLOSED/periode arsip menolak mutasi dokumen/realisasi/LPJ/acara/form terkait dan menutup penerimaan pendaftaran secara efektif. Histori tetap dapat dibaca sesuai izin. Jejak menautkan Proker beserta tab P1, acara/form periode lama dan short link. Inventaris tetap lintas periode agar barang dan riwayat pinjamannya berlanjut.

## Batas awal

- Berkas raw streaming: PDF, PNG, JPEG, WebP, TXT, CSV; maksimal 20 MiB, ekstensi/MIME/signature cocok, tidak disajikan sebagai HTML inline. File besar/format lain memakai tautan Drive. Upload peserta tidak termasuk MVP P1.
- Form: maksimal 100 pertanyaan, 20 bagian, 50 opsi per pertanyaan; body pengiriman maksimal 128 KiB.
- Antispam: honeypot dan 20 kiriman per 15 menit per IP dengan counter PostgreSQL. Konfigurasi trusted proxy tetap perlu diuji pada deployment agar IP klien benar.
- Ekspor per versi: maksimal 10.000 respons dan 20 MiB payload jawaban. CSV streaming melindungi formula; XLSX memakai string cells dan spool 1 MiB sebelum disk. NIM tidak diubah menjadi angka.
- Kredensial tidak mempunyai kolom penyimpanan. Isian pola password/token eksplisit ditolak; ERP menyimpan rujukan vault/item, bukan isi kredensial.

## Database, storage, dan bukti

Revisi `0002_p1` menambahkan 13 tabel dan trigger immutable, tanpa mengubah baseline atau 20 tabel legacy. Target lokal sudah dimigrasikan dengan izin pengguna setelah backup mode 0600. Total: 30 tabel ERP dan 21 tabel lain termasuk metadata versi.

`ERP_MEDIA_DIR` dibaca melalui konfigurasi runtime; default lokal `Backend/var/media` ketika backend dijalankan dari Backend. Compose memakai volume private `erp_media` pada `/app/var/media`; Next mengizinkan body 21mb agar batas backend 20 MiB dapat ditegakkan, Nginx source membatasi 20m. Runtime Compose/Nginx belum diuji.

Bukti akhir: 103 test lulus (44 integrasi PostgreSQL), 21 alur browser P1 dan 18 alur regresi browser P0 pada Next production. Overflow 320/390/1440 px lolos, screenshot diperiksa. Lihat [matriks bukti](REQUIREMENTS.md), terutama E15–E21. Pengujian memakai PostgreSQL existing yang disetujui dengan outer rollback dan storage sementara, tanpa akun operasional. Build/ESLint, browser P0/P1 dan ukuran file nyata diuji; UAT manusia, deployment, kapasitas VPS, backup off-host dan restore pasangan DB+media operasional tetap belum terbukti.
